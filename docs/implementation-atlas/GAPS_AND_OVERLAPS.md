# Focused Track 7 design findings — 2026-10-15

The following are **research findings/proposals, not implemented fixes**. MasterIndex already has conflict type/namespace metadata, but write callbacks can fail after physical commit and startup rebuild only handles an empty index (`embers/index/master.py:98-159`; `embers/engine/writer.py:64-96`; `embers/db.py:175-187`). This is an index-health integration gap, not proof that a dedicated conflict index is needed. The present conflict query's unrelated-record reads also perform incidental physical verification; independent maintenance should own namespace-wide auditing (`embers/db.py:903-959`; `embers/maintenance.py`). ELLA's full-state event and native reducer can support verified warm-state reuse, but no cross-operation trusted current head exists (`embers/cognitive/epistemic.py:25-40,96-113,275-302`).

Additional concurrency questions: `map_conflict` checks for an existing pair before writing without one enclosing operation lock (`embers/db.py:789-901`); status transition calls `update` without its available `expected_hash` CAS (`embers/db.py:961-1000`; `embers/engine/writer.py:98-176`). These are risks to test and decide, not proven live failures. The full design and open contract gates are in `track7_atlas_design_20261015/07_DECISION_RECORD.md`.

**Existing-mechanism correction, 2026-10-15:** Native WAL recovery already protects immutable source record publication; native supersession sidecars, memory CAS and `audit_write` already protect or explain their respective write/history paths. Promotion Engine routes pending proposals for Automatic, Consensus, Human or Hybrid admission, and the Conflict Engine has explicit open-queue/status review. None of those is a strict whole-namespace physical/index audit, and none certifies a stale nonempty MasterIndex. The prior suggested durable generation marker and ELLA head pointer are alternatives, not proven minimum requirements; first evaluate existing physical-ID enumeration, lock, journal replay and rebuild. See `track7_atlas_design_20261015/08_EXISTING_MECHANISM_RECONCILIATION.md`.

**Roadmap correction, 2026-10-15:** The V1 table's “exact persisted impact remains unmeasured” and its closing call for a persisted measurement are superseded by the Phase 2 isolated 50-report measurement (last-five append median 1,929 ms); production-scale impact is still unmeasured. The new `09_COMPLETE_UPGRADE_ROADMAP.md` uses that baseline only after correctness gates. It identifies no second WAL/index/history/governance engine as necessary. Specific remaining gaps are certified derived-index completeness, conflict-only operation serialization, an approved promotion/current-status policy, strict independent audit status/reporting, and reusable ELLA state with an explicit old-event integrity boundary. The latter policy and crash/cross-process behavior remain unverified until implementation tests; see `10_REGRESSION_AND_RECOVERY_MATRIX.md` and `11_REUSE_AND_POLICY_DECISIONS.md`.

**Batch 1 correction, 2026-10-16:** The certified MasterIndex/conflict lookup and conflict-only serialization gaps above have local source implementations and isolated regression evidence (`12_BATCH1_IMPLEMENTATION_EVIDENCE.md`). Full startup/behind reconciliation is deliberately distinct from healthy lookup. Healthy conflict lookup no longer reads unrelated memory bodies, though its candidate seal scans in-memory metadata. Native WAL checkpoint still does not itself attest index state; the new source/applied epoch protocol does. Remaining gaps: mixed-version deployment must avoid old writers that do not advance the epoch; arbitrary old-byte tampering still requires independent audit; real power-loss durability and live behavior are unverified. Promotion policy, independent audit reporting and ELLA state reuse are unchanged.

## Batch 2 gap correction — 2026-10-17

Promotion/current-status integration now exists in local source with isolated tests (track7_atlas_design_20261015/13_BATCH2_IMPLEMENTATION_EVIDENCE.md). Graph relations remain history rather than status authority. Proposal promotion/rejection now share lock/CAS; the tested interruption resumes one promoted memory. This does not supply a verified human role, override reason/version contract, single multi-record native transaction or real power-loss proof. Conflict-related manual override remains blocked. Independent audit and ELLA acceleration are still gaps. Ember Control Center is a future administrative interface, separate from the read-only Research Observatory.
## Batch 3 remaining boundaries — 2026-10-17

Independent audit is now a maintenance diagnostic, distinct from per-write `audit_write`, touched-record verification, semantic conflict review and promotion. It does not add a new memory authority. The current API is DB-backed: a store that fails startup reconciliation on corrupt physical source cannot expose its stored audit report through that API, although the sidecar remains available to a local operator. No verified administrative role/scope authorizes whole-store agent audits or agent-triggered repair; neither surface was added. Undecodable physical files have unknown namespace and are reported without sensitive identity in scoped results, preventing certification. Real power-loss and production-scale scan behavior are unverified; Batch 4 remains open.
