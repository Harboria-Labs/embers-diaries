## Correction to the previous design notes

`02_CONFLICT_RETRIEVAL_DESIGN.md` correctly rejects uncertified type-only filtering, but its durable generation/dirty-marker protocol is **one possible implementation**, not a proven prerequisite. Existing physical-ID enumeration, WAL recovery, atomic sidecars and full rebuild should be evaluated first. A query-time ID-set comparison alone cannot detect wrong type metadata, so a trustworthy reconciliation/audit boundary is still needed. `04_INCREMENTAL_ELLA_DESIGN.md` likewise over-prioritized a new durable journal head: existing `all_ids()` plus lock can detect new/missing sequence IDs without replaying event bodies, although it does not provide instant detection of old-file tampering. `03_INTEGRITY_AUDIT_DESIGN.md` must be read with `audit_write`'s existing per-write role and Promotion/Conflict review routing in view. None of these corrections marks a proposed optimization as implemented.

## Smallest next contract to settle

Specify whether an independent completed audit may attest to old ELLA events and MasterIndex metadata between audits, including the response to out-of-band file edits and audit failures. Then use existing WAL/lock/sidecar/rebuild machinery for focused integration tests. If exact per-request detection of any historical byte change remains mandatory, accelerated reads cannot simply skip old record verification; that cost/guarantee choice must be explicit before implementation approval.
