## Execution discipline after approval

1. Record baseline assertions on the exact implementation snapshot before each batch. Add one failing targeted test per intended behavior, then make the minimal source change. Stop on a correctness failure; do not advance batches.
2. Use unique temporary isolated stores and child processes. Do not point fixtures at `ember_store`, the installed live native binary, the running service or the permanent ngrok tunnel. A Rust source change, if later justified, requires separate source/native consistency proof before comparing behavior.
3. Capture the order of durable steps and the injected failure point. An exception after a committed write is different from a failed write; an interrupted index callback is derived-state failure. Reopen from the same isolated store and compare source records, history and query results.
4. Run the Phase 2 isolated ELLA workload only after all Batch 4 correctness gates pass; report environment, fixture sizes, raw timings, median and disk use alongside the prior numbers. The historical benchmark is not a production capacity claim.
5. At each batch exit, update Atlas source version, coverage, exact executed tests and remaining uncertainties, then update the canonical Production × Research Map in its separate columns.
