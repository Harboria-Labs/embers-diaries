# Counterexamples and error semantics

All mutations described below were confined to newly created disposable stores. `03_EQUIVALENCE_MATRIX.csv` includes exact ordered `Conflict.to_dict()` output or exception class/message for the reference and each candidate.

1. **Untagged conflict.** A valid sealed CONFLICT record with no `conflict` tag was written directly through `db.write`. The reference returned it; the tag prefilter missed it. Tags are not the conflict authority.
2. **Missing graph edge.** A mapped conflict record remained after its CONTRADICTS graph edge was removed in the disposable fixture. The reference still returned it; the graph gate returned empty. This remained true after reopening the store. A graph edge cannot be the only admission signal.
3. **Stale type metadata.** In one fixture the in-memory MasterIndex type for a valid CONFLICT record was changed to DOCUMENT. The reference read the record and returned it; the type prefilter missed it. A second fixture checkpointed the index, deliberately altered the persisted `record_type` field, reopened the store, and reproduced the mismatch. This models stale/corrupt index metadata, not a normal API write.
4. **Unrelated record integrity error.** An unrelated DOCUMENT file in a disposable store was modified after sealing. The reference raised `RecordIntegrityError` while scanning namespace records. Type, tag and graph candidates skipped that record and returned values, so none matched the error behavior. No candidate may claim unconditional equivalence if this fail-closed behavior is required.
5. **Malformed conflict payload.** A sealed CONFLICT record with the same memory ID at both endpoints caused the reference to raise `ValueError` even when queried for another target. The type and tag candidates also raised in the tested case. Graph gating may still miss such an error for a target with no contradiction edge; that exact variant was not run before the disk stop.
6. **Stale endpoint.** A valid CONFLICT record referring to a missing peer memory was still returned by the reference when queried from its existing endpoint. Type metadata filtering matched; graph gating happened to match only because other mapped graph edges existed for that target. The reference does not require a live peer at lookup time.

Normal cases matched on exact order and payload for no conflicts, one/multiple active conflicts, duplicate-map idempotency, closed and superseded heads, cross-namespace records, and missing-target/authorization exceptions. The strict conclusion is **no fully equivalent narrow candidate has been established**.
