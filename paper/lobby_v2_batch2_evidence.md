# Lobby V2 Batch 2 local evidence — 2026-10-18

Status: implemented and validated for the normal single-process server path. No live deployment or multi-worker cross-process push claim.

`embers/lobby/realtime_v2.py` provides Lobby-only SSE. Each provisional mutation appends an event in its SQLite transaction; listeners are signaled only after commit. A connected client receives item ID, version, change type, time and cursor, then retrieves context separately. Idle authorization heartbeats do not read the event log for delivery. `Last-Event-ID`/`after` resumes from an ordered bounded window; missed or invalid history emits `reset`. Grant/revoke changes wake local subscribers, and stream authorization is checked on every delivery and idle timeout. The event store is separate from the Observatory journal and permanent Ember records. Batch 1 files gain the cursor-floor column through an in-place migration.

Focused command: `diaries\Scripts\python.exe -B -m pytest tests/test_lobby_v2_batch2.py tests/test_lobby_v2_batch1.py tests/test_lobby.py tests/test_lobby_api.py -q -p no:cacheprovider --basetemp .test_lobby_v2_batch2_verified_20261018` — **28 passed**. Tests cover commit wakeup, restart cursor catch-up, missed-history reset, revocation, legacy Lobby behavior and Batch 1 file migration. The event watcher is process-local: another worker's commit is recovered on reconnect but cannot wake an already connected stream in this version. Cross-worker live push requires a supported shared notifier and remains unverified. No event polling was added to mask that limitation.
