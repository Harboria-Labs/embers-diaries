`embers/lobby/working.py` extends the Lobby with a separate SQLite provisional file beside each Ember store. It uses full-synchronous transactions, seven-day item TTL, 1,000 active items and 2,000 retained event hints per scope, and removes expired inactive rows after an additional TTL. The file is outside `.ember` records and the observation journal. Explicit owner-created scope, owner-granted membership, active owned session, matching namespace/task and namespace ACL gate operations. The REST surface is in `embers/api/lobby_v2.py`.

Items carry claim, kind, uncertainty, evidence status/references, author/session provenance, version and lifecycle. Submission requires `share=true` and a client key; equal retries return the same item, changed content with the same key is rejected. Only the author can correct or withdraw. Contextual query ranks active items by lexical overlap and recency without calling durable recall or FUR/ELLA. Evidence references use a separate authorized endpoint; normal item responses omit reference URLs, and cross-agent responses hash source session IDs. HTTPS reference reachability and external ACL are not certified by Ember.
