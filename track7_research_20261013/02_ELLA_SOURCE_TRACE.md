# ELLA execution trace

All paths below refer to commit `f183346547cd210f58ca0a6b23df91a56be22b66`; the working tree contained prior unrelated dashboard edits. Line numbers are source locations at that commit.

1. Evidence is attached by `EmberDB.attach_evidence` / `_write_evidence_record` (`embers/db.py:1633-1710`). An evidence record is stored and linked to a durable claim. `EpistemicLedger.apply` (`embers/cognitive/epistemic.py:103`) authenticates actor, validates request identity/revision/target and looks up attached evidence using `evidence_for` and `get_evidence` (`embers/db.py:1711-1731`). These include graph lookup and evidence reconstruction/verification.
2. `apply` calls `load` under the writer lock before each new action (`epistemic.py:110-111`). `load` enumerates *all* store IDs and filters/sorts ELLA IDs (`epistemic.py:25-27`, `storage/store.py:280-285`). This is O(M) directory enumeration for M total store records plus O(E log E) sorting E journal IDs.
3. For each of E events, `load` calls `EmberStore.read` (`store.py:260-278`), which reads, decodes and verifies the record if sealed. It then explicitly calls `record.verify_integrity()` again (`epistemic.py:28-34`). `EmberRecord.verify_integrity` canonicalizes the hash payload and hashes it (`core/record.py:207-227`, `core/integrity.py:58-65`, native `canonical_record_bytes` and `sha256_hex` in `rust/ember_core/src/lib.rs:918,282`). Verified: two full integrity computations per sealed journal record on this path. Both scale with event byte size.
4. `load` checks sequence, namespace, type, chain predecessor and `digest(event without seal)` (`epistemic.py:29-36`). It then initializes default policy and calls native `ella_reduce` once per event (`epistemic.py:37-39`). `domain.call` JSON encodes/decodes every call (`core/domain.py:7-8`); native `domain_call` parses JSON (`rust/ember_core/src/lib.rs:1130-1133`) then calls `domain::ella::reduce` (`domain/mod.rs:78`, `domain/ella.rs:236-243`). The reducer validates both current and next state and checks action-specific transitions. Since events embed the whole next state, processing an old event is not constant-size work.
5. `apply` scans all loaded events for idempotency, checks revision and target, builds next state, and projects before/after for assessment crossings (`epistemic.py:111-205, 228-251`). Projection reads target/evidence, gets conflicts, then calls native `ella_project` (`epistemic.py:46-101`, Rust `domain/ella.rs:245+`). The Rust project path builds evidence identities and units. Its repeated `aa.iter().any(...)` searches within assessment loops can be quadratic in assessment count for applicable confirmation cases. That is source-level risk, not isolated in this experiment.
6. `apply` validates next state, projects response, embeds `state=next_state` and `response=response` in the new event, calls `ella_reduce` again, seals the event, then writes an immutable record (`epistemic.py:300-328`). `EmberStore.write` uses a native transaction or WAL path (`store.py:194-239`); observation-journal delivery follows and is recoverable (`epistemic.py:329-339`). A real append therefore pays full load plus projection/validation, record serialization and durable write. Persisted append and WAL costs were **not measured** here.
7. Repeating `load` on the same object or a new object follows the same path; `EpistemicLedger` has no loaded-event or state cache (`epistemic.py:20-40`). Adding one event grows both the event count and the embedded state in later events. For a sequence of simple reports with one new assessment each, total embedded assessment copies are 1+...+E = O(E²), before responses/metadata. This is a source-derived size bound for this fixture, not a general measured asymptote.

Complexity notation: M = all store records, E = ELLA events, B = sum of encoded ELLA event bytes, A = current assessment count. A load includes O(M) enumeration, O(E log E) sort, O(B) record decode/hash/chain work, and replay that repeatedly validates growing states (at least O(B) under these report events). Native boundary JSON copies also scale with the growing input states. Exact constants and worst cases remain unmeasured.
