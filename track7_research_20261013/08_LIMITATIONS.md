# Limits, incomplete work and open questions

1. **Persisted ELLA not run.** At 344 MB free, the earlier 2 GB reserve was not met. No disposable on-disk store was created. Consequently fixture creation time is in-memory construction, not authenticated evidence attachment; sequential append latency, per-event append latency, actual WAL cost, journal-file size and cold-cache latency remain unmeasured.
2. **Synthetic reports.** The fixture uses native-validated report transitions and production `EpistemicLedger.load`, but bypasses `EpistemicLedger.apply` and has empty response bodies. It measures ELLA's replay mechanism, not the complete user operation. It includes no corrections, invalidations, merges, carries, conflicts or evidence attachment. Generalizing its growth to those actions would be unsupported.
3. **Stage timings overlap in mechanism and vary by run.** Independent stage passes cannot be subtracted from a whole-load run. The `native_replay_boundary` includes JSON serialization and parsing on both sides, not Rust execution alone. `cProfile` percentages and cumulative times are not causal attribution.
4. **Resource visibility.** `tracemalloc` sees Python-tracked allocations only. Process CPU time on this Windows host has coarse resolution; RSS, disk IO, energy and system-wide CPU were not captured. The encoded bytes are an in-memory proxy, not physical store size.
5. **Broader Track 7.** LADC, FUR, Pairing Matrix and ordinary recall received source inspection in this run, not new focused measurements. Historical Track 7 memory-only Pairing/LADC results (from an earlier native module) are directionally useful but not current-build evidence: 10,000-edge Pairing best-last median 531.04 ms; LADC 0 direct/2048 prior median 272.86 ms. They should be rerun before performance claims about this deployed build.
6. **Live service.** Only local `/health` and the local ngrok tunnel inspector were read. The inspector reported the configured public hostname pointing to `127.0.0.1:9200`; no public endpoint request, live memory write, or live recall was performed. Namespace isolation was not treated as store isolation. A read-only Win32 process inventory request was denied by CIM permissions, so process IDs were not re-established in this run. The health response is not proof of all subsystems' continuing health.
7. **Scaling inference.** Four sizes through 50 synthetic events show increasing cost but do not justify a universal complexity exponent. The source-derived repeated full state copies explain a plausible superlinear mechanism. Hardware, scheduling, filesystem and Colab fixture differences prevent direct absolute-latency comparison.

The most important unanswered question is the relative cost of full ELLA load versus projection, record write, WAL and observation delivery during a real append. Answer it only after genuine storage capacity is available for a separate disposable store.
